05
🔧
Diagnostic de bugs & optimisation de performances en environnement contraint

Identifier et résoudre des problèmes techniques complexes dans des environnements industriels contraints (pas d'internet, CDN bloqués, performances temps réel critiques). Optimiser le rendu graphique, filtrer les données bruitées, concevoir des solutions robustes et maintenables. Capacité à itérer sur une architecture sans considérer les changements de direction comme des échecs.

Throttle / Debounce LTTB décimation (8000 pts) Filtrage percentile 98 setInterval / needsUpdate (30 FPS) Moyenne glissante (20 pts) Admin Linux · DKMS · Secure Boot
📎 5 problèmes techniques résolus au cours du stage : (1) fréquence chaotique (jitter WiFi → calcul Python côté serveur) ; (2) timestamps CSV non monotones (tri + ordre temporel) ; (3) freeze navigateur à 10 000 Hz (setInterval 33ms + flag needsUpdate) ; (4) aberrations d'échelle fréquence (filtre période min + plafond Nyquist + percentile 98) ; (5) zoom lent sur longues acquisitions (throttle 100ms + debounce 120ms + LTTB à 8 000 points). Administration Debian 13 : installation drivers NI en dépaquetant manuellement des .deb Ubuntu, désactivation Secure Boot, recompilation modules noyau via DKMS.

03 · Parcours du stage

3 phases, 1 livrable industriel

L'IHM BCST (Faure Herman, Avr–Juil 2026) — projet principal du stage, développé en 3 itérations successives.

Phase 1 · Semaines 1–2
Prototypage ESP8266 + GBF

Validation des principes de traitement du signal et d'affichage web. Acquisition série Arduino → Python → Node.js/Socket.io → Chart.js. Interface fonctionnelle mais limitée à l'affichage de tension brute sans horodatage réel.

ESP8266 Arduino IDE Python serial Node.js Chart.js
Phase 2 · Semaines 3–4
Migration ESP32 dual-core

Architecture dual-core sous FreeRTOS : un cœur pour l'acquisition, un pour le WiFi, séparés par un ring buffer volatile. Introduction du calcul de fréquence et du mode historique CSV. Découverte et résolution de 2 bugs critiques (timestamps non monotones, fréquence instable).

ESP32 FreeRTOS Ring buffer CSV historique Zéro-crossing (JS)
Phase 3 · Semaines 5–12 (production)
Architecture National Instruments — Solution industrielle finale

Adoption de l'écosystème NI pour répondre aux exigences de précision métrologique industrielle. Chaîne complète : NI cDAQ-9174 + NI9202 (10 000 Hz) → Python/nidaqmx → MQTT/Mosquitto → Node.js/Socket.io → navigateur/Chart.js. Fonctionnalités complètes : modes Acquisition/Contrôle, popups de configuration, sélection CSV (15 derniers + import externe), génération de PDF de qualification (LaTeX/pdflatex), pilotage de 3 sorties digitales NI9472, toolbar de statut (rouge/vert/bleu), zoom performant (LTTB + throttle/debounce). Déployé en production sur le banc BCST, accessible depuis tout le réseau Faure Herman.

NI cDAQ · nidaqmx Python avancé MQTT · Mosquitto Node.js · Express · EJS Socket.io SQL Server · mssql LaTeX · pdflatex Debian 13 Git workflow pro
